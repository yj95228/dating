# 💘 소개팅 주선 노트

지인 소개팅을 위한 **후보 관리 · 프로필 공개 동의 · 관심 신청** 웹앱입니다. 관리자는 로그인해 후보를 관리하고, 참여자는 계정 없이 공유 링크를 이용합니다.

**운영 주소:** https://dating-note.vercel.app

> 새 기능은 [PR #6](https://github.com/yj95228/dating/pull/6)에서 작업 중입니다. 실제 운영 화면에는 **main 머지 후** 표시됩니다. 마이그레이션과 Edge Function은 웹앱 배포와 별도로 적용됩니다.

## 이용 흐름

| 사용자 | 접속 방식 | 할 수 있는 일 |
| --- | --- | --- |
| **관리자** | 이메일/비밀번호 로그인 | 후보·사진·상태·매칭·관심 신청 관리, 공개 동의 링크 발급 |
| **후보 본인** | 개인별 `/consent/:token` | 관리자 보관 동의와 비회원 공개 동의를 각각 선택, 철회·삭제 요청 |
| **소개팅 참여자·중간 주선자** | `/i-need-money` + 공통 접속 코드 | 동의된 후보 열람, 관심 후보 선택·신청 |
| **기존 viewer 계정** | 기존 로그인 | 과거 계정 호환용. **새 사용자 초대는 중단**되며 기존 접근 권한은 자동 삭제하지 않음 |

### 1. 후보 등록과 동의받기

1. 관리자가 **인물**에서 후보를 등록하고 공개될 프로필을 확인합니다.
2. **후보 상세 → 🔐 개인정보 동의 관리 → 동의 링크 만들기**에서 개인별 링크를 복사합니다. 기존 이름에 붙인 ‘건너’ 표기와 직접/건너건너 구분은 그대로 사용하며 **중간 주선자의 이름을 별도로 입력할 필요는 없습니다.**
3. 링크를 본인에게 직접 전달하거나 소개를 연결해준 사람을 통해 전달합니다.
4. 프로필 당사자는 회원가입 없이 **이름·사진을 포함한 관리자 보관 정보의 항목**과 실제 비회원 공개 항목을 확인합니다. **후보 관리 목적 수집·이용(참여 시 필요)**과 **비회원 공개(선택)**를 별도로 결정합니다.
5. **활성 + 내부 관리 동의 + 비회원 공개 동의 + 현재 공개 프로필이 동의 당시와 동일**한 후보만 비회원 페이지에 나타납니다.

**비회원 공개(선택)를 거절해도 관리자 내부 관리는 가능합니다.** 공개에 동의하지 않은 후보는 비회원 페이지뿐 아니라 기존 viewer 계정의 조회 화면에서도 제외됩니다. 관리자만 내부 관리용 데이터를 봅니다. 두 동의 모두 거절하거나 내부 관리 동의를 철회하면 기존 정보의 삭제 요청이 기록되고, 관리자가 인물·이미지 등의 실제 삭제를 처리해야 합니다. 동일 링크에서 비회원 공개만 철회할 수도 있습니다.

> 직접 받거나 중간 주선자를 통해 전달받은 **이름과 사진도 수집·이용 안내 대상**입니다. 전달받았다는 사실만으로 후보 본인의 동의가 있었다고 간주하지 말고, 출처를 설명할 수 있도록 관리하세요. 동의 요청 중 임시로 보관한 개인정보도 이용 목적과 필요성이 사라지면 정리해야 합니다.

### 2. 소개팅 링크와 관심 신청

- **공유 주소:** https://dating-note.vercel.app/i-need-money
- 관리자 **💌 신청 → 🔐 접속 코드**에서 하나의 공통 코드를 설정해 전달합니다. **링크와 코드 모두를 아는 사람**은 접속할 수 있으며, 제3자 재전달 가능성은 남습니다.
- 첫 입장 때 `소개팅 성사되면 주선비 입금 부탁드려요 🙇` 체크박스와 접속 코드를 입력합니다. 체크박스는 실제 결제 약속/청구가 아닙니다.
- 접속 인증은 **30일 유지**, 공통 코드 변경 시 기존 인증은 무효화됩니다. 5회 오류 시 15분 차단합니다.
- 후보는 성별·직접 아는 사이/건너건너 아는 사이별로 탐색하고 관심 신청을 남길 수 있습니다. **같은 기기에서 동일 후보 집합·닉네임·신청 유형으로 중복 접수하면 차단**하지만 다른 후보로 재신청하는 것은 가능합니다.

### 3. 공개 정보와 동의 기간

| 비회원에게 공개 | 비회원에게 미공개 |
| --- | --- |
| 성별, 출생연도, 키, 지역, 직장/직업, 주선자와의 관계 구분, 이상형, 특징 | 이름, 사진, 매칭 이력 |

※ **특징(`people.note`)은 비회원에게 공개**되므로 내부 비밀 메모나 식별성 높은 개인정보를 넣지 마세요.

- **180일 자동 재동의는 사용하지 않습니다.** 후보가 소개팅 주선에 참여하고 공개 동의를 유지하는 동안에만 공개하며, 공개 동의 철회·주선 종료·비활성 처리 시 중단합니다.
- **기존 180일 안내에 동의한 후보는 공개 기간 변경을 승인하지 않은 상태이므로 재동의가 필요**합니다. 서버는 이전 동의를 자동 승계하지 않고 정책 버전으로 구별합니다.
- 공개 프로필 내용이 달라지면 **자동 비공개 → 후보 재동의 후 재공개**됩니다. 단순 정렬 순서 변경은 재동의 대상이 아닙니다.
- 소개팅 목적을 달성해 불필요해진 개인정보는 파기 등 별도 조치가 필요합니다. **공개 중단과 개인정보 삭제는 다릅니다.**
- 특정 링크를 받은 사람이 실제 후보 본인인지 사이트가 자동 인증하지는 않습니다. **검증된 연락 경로로 전달**해야 합니다.
- 구 단위 거주지나 회사명도 다른 프로필 정보와 결합하면 개인정보가 될 수 있습니다.

## 주요 기능

| 관리자 | 비회원 |
| --- | --- |
| 인물 추가·수정·삭제, 상태(`활성 / 휴식중 / 비활성`) 변경 | 공개 동의한 후보만 보기 |
| 직접/간접 관계별 정렬 및 드래그 순서 변경 | 성별 및 관계별 구분 |
| 사진 업로드·갤러리, 이상형/특징, 매칭 결과 | 관심 후보 선택·신청 |
| 후보 동의 링크 발급·재발급·공개 중단·삭제 요청 확인 | 후보 본인의 관리자 보관 동의 / 비회원 공개 선택 / 철회 |
| 신청 분류·검색·처리·푸시 알림 | 로그인 없는 접속 코드 방식 |
| PWA 지원, 작성 중 인물 추가 초안 복원 | 모바일 브라우저 이용 |

## 기술 스택

| 구성 | 기술 |
| --- | --- |
| 프런트엔드 | React 18 · TypeScript · Vite · React Router |
| 데이터 · 인증 | Supabase PostgreSQL · Auth · RLS · Edge Functions |
| 사진 | Cloudinary |
| 배포 | Vercel · PWA |
| UI | 공통 스타일 객체 + 인라인 스타일 |

### 프로젝트 구조

```text
src/
  pages/               # 관리 화면, 비회원 목록, 후보 동의 페이지
  components/          # 카드, 입력 폼, 동의 관리 패널
  hooks/               # 인증 및 인물/매칭 상태
  lib/                 # Supabase, 초안 저장 등
supabase/
  functions/
    guest-share/        # 공통 접속 코드·후보 목록·관심 신청
    guest-consent/      # 후보별 공개 동의·철회·관리자 링크
    create-invite/      # 구형 초대 API: 신규 초대 중단
  migrations/           # 데이터베이스 변경 이력
scripts/                # 개발/회귀 검사
```

## 로컬 실행

```bash
npm install
cp .env.example .env
npm run dev
```

`.env`에 Supabase URL/공개 키 및 Cloudinary 클라우드명/unsigned 업로드 preset을 설정합니다. **Supabase `service_role` 키는 절대 `VITE_*` 환경변수나 프런트엔드에 넣지 마세요.**

```bash
npm run typecheck
npm run build
npm run test:auth
npm run test:app
```

모바일 같은 Wi-Fi에서 테스트하려면 `npm run dev -- --host 0.0.0.0`을 사용합니다.

## 운영·배포

Supabase 마이그레이션, Edge Function 배포 순서, 권한 검증, PWA 캐시 대응 등은 **[운영 가이드](docs/OPERATIONS.md)**를 참고하세요.

**주의:** 웹 앱 머지 전에도 Edge Function이 먼저 적용될 수 있습니다. 현재 동의 완료한 후보가 없다면 비회원 공유 목록이 비어 있는 것이 정상입니다. 기존 viewer 로그인 계정은 별도이며, 새 초대 UI가 없어져도 기존 접근 권한이 자동으로 회수되지는 않습니다.
