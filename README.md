# 💘 소개팅 주선 노트

지인 간 소개팅을 돕는 **후보 관리 · 개인정보 동의 · 프로필 열람 · 관심 신청** 웹앱입니다. 관리자는 계정으로 후보를 관리하고, 후보 본인과 소개팅 참여자는 개별 링크를 통해 이용할 수 있습니다.

- **서비스:** https://dating-note.vercel.app
- **소개팅 신청:** https://dating-note.vercel.app/i-need-money
- **배포·운영 가이드:** [docs/OPERATIONS.md](docs/OPERATIONS.md)

## 누가 어떻게 이용하나요?

| 이용자 | 접속 | 주요 기능 |
| --- | --- | --- |
| 관리자 | 이메일·비밀번호 로그인 | 인물·사진·매칭·신청 관리, 개인정보 동의 링크 발급, 공개 프로필 미리보기, 알림 설정 |
| 등록된 후보 본인 | 개인 동의 링크 (`/consent/:token`) | 공개 프로필 확인·수정, 정보 보관/공개 동의, 거절·철회·삭제 요청, 개인 열람 링크 받기 |
| 신규 참여자·소개자 | `/i-need-money` 또는 소개자 링크 | 이용 신청 및 승인 후 후보 열람·관심 신청 |
| 기존 viewer 계정 | 기존 로그인 | 기존 계정에 한해 제한적으로 이용. 신규 계정 초대는 중단 |

별도 회원가입 없이 이용하는 개인 링크는 **본인 확인을 자동으로 보장하지 않습니다.** 운영자가 실제 당사자에게 신뢰할 수 있는 경로로 전달해야 합니다.

## 1. 후보 등록과 개인정보 동의

1. 관리자가 **인물**에 후보 정보를 등록하고, 상세 화면의 **🔐 개인정보 동의 관리**에서 개인 동의 링크를 만듭니다.
2. 후보 본인은 공개될 항목을 확인합니다. 출생연도·키·거주지·직장/직업·이상형·특징은 **직접 수정**할 수 있으며, 수정한 최종 내용과 동의 선택이 함께 저장됩니다. 성별·관계 구분·이름·사진·매칭 이력은 관리자에게 수정 요청합니다.
3. **개인정보 수집·이용(필수)**과 **다른 사람에게 프로필 공개(선택)**를 각각 결정합니다. 안내문에는 핵심 내용이 보이고 자세한 사항은 펼쳐볼 수 있습니다.
4. 정보 보관에만 동의하면 관리자 내부 관리만 허용됩니다. 공개에 동의한 후보만 소개팅 열람 목록에 표시됩니다.
5. **동의하지 않기·저장 정보 삭제 요청**, 공개 중단, 전체 동의 철회, 동의 내용 변경도 지원합니다. 삭제 요청은 관리자에게 전달되며 실제 데이터·사진 삭제는 별도 처리해야 합니다.

동의한 후보는 개인 프로필 열람 링크를 받아 다른 후보를 살펴볼 수도 있습니다. **링크 재발급 시 이전 동의 링크는 무효화**됩니다.

### 공개되는 정보

| 공개 프로필 | 다른 참여자에게 보이지 않는 정보 |
| --- | --- |
| 성별, 출생연도, 키, 지역, 직장/직업, 주선자와의 관계 구분, 이상형, 특징 | 이름, 사진, 매칭 이력 |

**주의:** 특징(`people.note`)은 공개 항목입니다. 운영자 전용 메모나 민감한 정보를 넣지 마세요. 이름·사진은 비회원에게 보이지 않지만 **관리자가 보관하는 개인정보에는 포함**됩니다.

공개는 **활성 상태 + 유효한 정보 보관 동의 + 별도의 공개 동의 + 동의 당시와 일치하는 현재 공개 프로필**을 모두 만족할 때만 허용됩니다. 공개 내용이 변경되면 다시 확인·동의하기 전까지 공개가 중단됩니다. **180일마다 자동 재동의를 요구하지는 않습니다.** 목적이 끝나거나 동의를 철회하면 공개를 중단하고, 필요 없어진 원본 개인정보도 별도로 정리해야 합니다.

## 2. 개인 링크로 소개팅 참여하기

- **기존 등록 후보:** 보관·이용 동의 후 개인 열람 링크를 발급받습니다. 추가 관리자 승인 없이 이용할 수 있습니다.
- **신규 참여자:** 이름, 이용 목적, 소개 경로를 제출하고 관리자 승인을 받은 후 이용합니다. 소개자가 전달한 초대 링크도 사용할 수 있습니다.
- **브라우저 인증:** 처음 이용한 브라우저가 등록됩니다. 다른 기기·브라우저에서는 기존 인증 브라우저에서 **9자리 연결번호**를 승인해야 합니다.
- **친구 공유:** 개인 인증키가 포함되지 않은 일반 소개팅 링크를 공유합니다. 다른 사람의 개인 링크를 받은 사람은 본인 명의로 별도 이용 신청해야 합니다.
- **프로필 탐색·관심 신청:** 동의가 유효한 후보만 탐색하고 관심을 신청합니다. 등록 후보가 열람할 때 본인 및 과거 매칭 상대는 목록·신청 대상에서 제외됩니다. 연락처를 직접 입력받지 않고 관리자가 소개 가능 여부를 확인합니다.

## 3. 관리자 기능

- **인물:** 후보 등록·편집·삭제, 사진 갤러리, 성별·관계·상태 필터, 정렬 순서 변경, 임시 작성 내용 복원
- **매칭:** 소개 진행·결과 기록, 기존 매칭 상대 제외에 활용
- **💌 신청:** 관심 신청 검색·상태 처리, 신규 방문자 승인, 소개자 링크 관리, 외부에 보이는 **공개 프로필 미리보기**
- **개인정보 동의 관리:** 후보별 동의 상태 확인, 링크 발급·재발급, 즉시 공개 중단, 삭제 요청 확인
- **설정:** 기기별 관심 신청 푸시 알림
- **PWA:** 모바일 홈 화면에서 이용 가능하며, 새 버전이 준비되면 새로고침을 안내해 작성 중인 내용을 보호

## 기술 구성과 개발

| 영역 | 사용 기술 |
| --- | --- |
| 웹 | React 18, TypeScript, Vite, React Router |
| 데이터·로그인 | Supabase PostgreSQL, Auth, RLS, Edge Functions |
| 이미지 | Cloudinary |
| 배포 | Vercel, PWA |

```text
src/pages/            화면: 인물, 매칭, 신청, 동의, 프로필 열람
src/components/       입력 폼, 동의 관리, 공통 UI
src/hooks/            로그인과 데이터 상태
src/lib/              Supabase 클라이언트, PWA 업데이트 등
supabase/functions/   guest-consent, guest-share, guest-portal 등
supabase/migrations/  DB 스키마 및 정책 변경
scripts/              개발·회귀 테스트
docs/OPERATIONS.md    배포·운영·보안 안내
```

로컬 개발과 검증:

```bash
npm install
cp .env.example .env
npm run dev

npm run typecheck
npm run build
npm run test:auth
npm run test:app
npm run docs:check
```

`.env.example`을 참고해 Supabase 공개 URL·키와 Cloudinary 업로드 설정을 입력합니다. **`service_role` 등 서버 비밀키를 `VITE_*` 변수나 프런트엔드 코드에 넣으면 안 됩니다.**

## 운영·배포 시 확인할 점

웹 화면(Vercel), DB 마이그레이션, Supabase Edge Functions는 **별도로 배포**됩니다. 이 README는 저장소의 기능과 사용법을 설명하며, 배포 상태에 따라 실제 운영 사이트에서 일부 기능을 아직 사용할 수 없을 수 있습니다.

특히 **프로필 직접 수정과 동의 동시 저장**에는 `submit_guest_profile_decision` DB 함수 및 최신 `guest-consent` Edge Function이 필요합니다. 마이그레이션 이력 불일치로 **DB 자동 배포는 잠겨 있으므로**, 운영 DB 적용 상태를 확인하고 필요한 서버 변경을 먼저 배포해야 합니다. 배포 방법과 보안 점검은 [운영 가이드](docs/OPERATIONS.md)를 따릅니다.
